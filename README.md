# RansomShield EDR Command Center

A ransomware detection platform: a Python/FastAPI backend that watches
a sandboxed folder for suspicious file activity (mass modify/rename/
delete, honeypot tampering) and scores the risk in real time, plus a
web dashboard that shows everything live.

## What's in here

```
ransomshield/
├── backend/
│   ├── main.py              FastAPI app - all API routes + startup wiring
│   ├── file_monitor.py       Watches sandbox/ for filesystem events
│   ├── detection/
│   │   ├── behavior_engine.py  Scores risk from recent file activity
│   │   └── risk_engine.py
│   ├── event_manager.py      Persists every detected event to logs/events.json
│   ├── incident_manager.py   Opens/tracks incidents when risk escalates
│   ├── honeypot.py           Creates decoy files that trigger CRITICAL alerts
│   ├── security_state.py     In-memory live state shared across the app
│   └── config.py             Central, absolute-path config (run from anywhere)
├── frontend/
│   ├── index.html            Dashboard / Threat Monitor / Events / Risk / etc.
│   └── app.js                Polls the API every 2s and renders live data
├── sandbox/                  The folder actually being monitored (demo data)
├── logs/                     events.json / incidents.json (auto-created)
└── requirements.txt
```

## How it fits together

1. On startup, the backend creates 5 honeypot files under
   `sandbox/honeypots/` and starts a filesystem watcher on `sandbox/`.
2. Any create/modify/rename/delete under `sandbox/` is scored by the
   behavior engine (bursts of renames + deletes = ransomware-like
   behavior). Every event is logged; a risk escalation or a honeypot
   touch opens an incident automatically.
3. The frontend polls `/status`, `/events`, `/incidents`, and
   `/honeypots` every 2 seconds and updates the dashboard live - no
   manual refresh needed.
4. The frontend is served **by the same FastAPI app**, so there's no
   separate frontend server and no CORS configuration to worry about.

## Running it

```bash
cd ransomshield
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
uvicorn backend.main:app --reload
```

Then open **http://127.0.0.1:8000/** in your browser. That's it - the
dashboard, API, and file watcher all run from that one command.

Interactive API docs (auto-generated by FastAPI) are at
**http://127.0.0.1:8000/docs**.

## Trying it out without real ransomware

Click **"Run Simulation"** in the sidebar. This safely creates a
batch of test files inside `sandbox/documents/`, renames them (like
encryption would), then deletes them - all through the real watcher
and detection engine, not faked data. Watch the risk score climb on
the Dashboard and an incident appear under Incidents.

To also demonstrate the honeypot trip-wire, call the endpoint
directly with `trigger_honeypot: true`:

```bash
curl -X POST http://127.0.0.1:8000/simulate \
  -H "Content-Type: application/json" \
  -d '{"trigger_honeypot": true}'
```

Click **"Reset Demo State"** to clear events/incidents/counters and
start over.

## API reference

| Method | Path | Purpose |
|---|---|---|
| GET | `/status` | Current risk score, status, live activity feed |
| GET | `/events?limit=100` | Recent logged filesystem events |
| GET | `/incidents?limit=50` | All incidents, most recent first |
| GET | `/incidents/{id}` | Single incident detail |
| POST | `/incidents/{id}/status` | Update an incident's status |
| GET | `/honeypots` | Honeypot deployment status |
| POST | `/simulate` | Trigger a safe simulated attack |
| POST | `/reset` | Clear all demo state |
| GET | `/health` | Basic health check |

## Notes / known limitations

- State (risk score, activity feed) lives in memory and resets if the
  server restarts; events and incidents persist to `logs/*.json`.
- The behavior engine's thresholds are tuned for demo purposes (a
  burst of a dozen files in a few seconds trips HIGH/CRITICAL) - for
  a real deployment you'd want to validate these against real usage
  patterns to avoid false positives on legitimate bulk operations
  (backups, syncs, etc).
- This monitors the `sandbox/` folder specifically, not the whole
  filesystem - that's intentional for a safe, demoable project.
